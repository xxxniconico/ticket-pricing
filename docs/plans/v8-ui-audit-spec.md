# V8 Dashboard UI Audit Spec

你是一位资深 UI/UX 审查专家。请对票务定价看板进行一次全面的 UI/UX 审查，输出结构化的优化建议报告。直接修改文件，不要只输出计划。

## 审查文件

- `dashboard/app_v8.py` (1354行，Streamlit 看板)
- `dashboard/style.css` (353行，暗色主题样式)
- 可选参考: `src/rule_engine.py` (模型乘数常量), `src/pricing_v5.py` (定价档位)

## 审查维度

从以下角度分析，每个维度给出评级（优良中差）和具体建议：

### 1. 信息架构 (IA)
- Tab 划分是否合理？哪个 Tab 过载？
- 数据流：main() → 各 Tab 是否高效？`load_csl_data()` 是否被重复调用？
- Tab 命名是否直观？

### 2. 视觉层次
- KPI 卡片是否提供了有效的注意力引导？
- 每个 Tab 的视觉入口是什么？（用户打开后第一眼看到什么）
- 颜色使用是否符合「红涨绿跌」规范？
- 字体层级是否分明？

### 3. 交互体验
- 哪些交互控件（slider/radio/toggle）可能让用户困惑？
- What-If 沙盒的预设情景是否够用？
- 历史定价页是全部展开还是折叠？是否符合用户偏好（已知用户不喜欢折叠，偏好全部直接展开）？
- 有没有缺少的反馈（加载态、空态、错误态）？

### 4. 代码质量
- 重复代码（`pred_args` 构建、策略卡片、规则 Pill 链、定价表）—— 标出具体行号
- 硬编码乘数值（1.15/0.80/0.78 等）是否应该从 `src/rule_engine.py` 的 `MULTIPLIERS` 导入？
- 哪些函数内部重新导入了已在 main() 中加载的数据？
- CSS 类命名是否有冲突风险？

### 5. 性能
- `@st.cache_data` 使用是否合理？
- Matplotlib 图表 vs HTML/CSS 手写渲染的性能对比
- 座位图 SVG 是否影响首屏渲染？

### 6. 移动端/响应式
- 当前布局在小屏幕上的表现
- Tab 在小屏幕上是否可点？
