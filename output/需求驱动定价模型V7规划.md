## 一、行业理论参照

### 1.1 航空收益管理（Yield Management）
- **核心**：同一航班座位按购买时间/渠道差异化定价，目标是最大化每座收入（RevPAS）
- **可借鉴**：球场各区=不同舱位，开售后按销售速度动态调价
- **关键指标**：Booking Curve（预订曲线）、Sell-through Rate（售罄率）

### 1.2 酒店收入管理（RevPAR）
- **核心**：房价=基础价×需求因子×竞争因子×时间因子
- **可借鉴**：每个区有基础价，周末/德比/暑假=需求因子
- **关键指标**：Occupancy Rate（上座率）、ADR（均价）

### 1.3 体育赛事动态定价（Dynamic Ticket Pricing）
- **MLB/NBA实践**：开售后价格随需求实时浮动，热门场次涨价、冷门降价
- **可借鉴**：比赛日临近→未售区降价倾销；德比→预售期涨价
- **关键指标**：Price Elasticity by Section、Secondary Market Premium

### 1.4 基于属性的定价（Attribute-Based Pricing）
- **核心**：价格由产品属性决定，而非打包成固定档位
- **可借鉴**：每个座位=视角质量+距离+遮阳+出口距离的综合价值

## 三、新定价模型架构

```
输入层               计算层                 输出层
───────            ─────────             ───────
总预测上座 ─┐
日期/对手  ─┤
历史分区占比 ─┼─→ 各区基准销量 ──→ 稀缺度因子 ──┐
区容量     ─┘                                  ├─→ 96区独立价格
用户复购率  ────────────→ 偏好溢价因子 ─────────┘
开售天数   ────────────→ 时间折扣因子 ─────────┘
```

### 3.1 Step 1: 计算各区基准销量

```
全区基准销量[区] = 总预测上座 × 该区历史占比(同量级)
```

历史占比按总上座分为 4 个量级：<6k / 6-9k / 9-12k / >12k

### 3.2 Step 2: 稀缺度定价

| 稀缺度 | 条件 | 调价 |
|:---:|------|:---:|
| 过热 | 预测需求 > 区容量×0.9 | +10% |
| 偏紧 | 预测需求 > 区容量×0.7 | +5% |
| 正常 | 预测需求 在 0.5-0.7 之间 | 原价 |
| 宽松 | 预测需求 < 区容量×0.5 | -5% |
| 滞销 | 预测需求 < 区容量×0.3 | -10% |

### 3.3 Step 3: 用户偏好溢价

按历史复购率（该区复购用户占比）分四档：

| 偏好等级 | 条件 | 溢价 |
|:---:|------|:---:|
| 铁粉区 | 复购率>40% 且 用户>5000 | +3% |
| 热门区 | 复购率>25% | 0 |
| 普通区 | 复购率10-25% | 0 |
| 冷门区 | 复购率<10% | -3% |

### 3.4 Step 4: 时间曲线

```
开售D-14: 基准价 × 0.90 (早鸟)
开售D-7:  基准价 × 1.00
开售D-3:  稀缺度价格
开售D-1:  若售罄率<50% → 再降5%
比赛日:   若售罄率>90% → 关闭；<50% → 现场促销
```

### 3.5 Step 5: 区价差约束

防止跨区挤出：相邻价格区价差 ≤ 30%

```
如果 S121(¥315) 和 S122(¥303) 价差 < 30% → OK
如果 T5 涨价后比相邻 T4 贵 > 30% → 调回上限
```

## 五、实施路线

### Phase 1: 基建（3天）
- `src/section_pricing.py` — 区级定价引擎
- `data/section_attributes.json` — 96区属性数据（视角/距离/容量）
- `data/section_demand_profile.json` — 各区历史占比曲线

### Phase 2: 集成（2天）
- 看板新增「区级定价」Tab
- 与现有预测引擎对接（输入总预测→输出96区价格）
- 保留原 T1-T6 优化器，新老并行

### Phase 3: 灰度（2周）
- 输出建议价，不实际执行
- 对比新老定价的模拟收入差异
- 用户反馈+业务确认

### Phase 4: 自动化（1周）
- 开售后按时间曲线自动调价
- D4/D7 销速接入→稀缺度实时更新
- A/B 测试框架

## 七、风险

| 风险 | 缓解 |
|------|------|
| 96 区定价过于复杂 | 初始按属性分 10 个价格带，再精细化 |
| 稀缺度计算不准 | 用历史 sell-through 曲线校准 |
| 时间折扣冲击收入 | 折扣仅对滞销区生效，铁粉区不折 |
| 球迷对频变价格反感 | 单场不超过 2 次调整，提前公告 |
